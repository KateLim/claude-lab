# 미래를 위한 배당 설계기 (로컬)

노후에 매달 얼마가 필요하고, 배당으로 얼마나 채울 수 있는지 계산하는 로컬 웹 서비스입니다.
`https://d35e21nev0myoj.cloudfront.net/` 와 같은 일을 내 컴퓨터에서 합니다.

```
python3 server.py                     # http://127.0.0.1:8770
./run.sh 9000                         # 포트 지정
python3 server.py --host 0.0.0.0      # 외부에서 접속 (인증 없음 — 아래 주의)
```

설치할 것이 없습니다. **파이썬 표준 라이브러리만** 쓰고, 프런트엔드도 빌드 단계 없이
브라우저에서 바로 도는 바닐라 JS입니다. `pip install`, `npm install` 모두 필요 없습니다.
파이썬 3.9 이상이면 됩니다.

계산은 전부 이 프로세스 안에서 돕니다. 인터넷은 세 가지에만 씁니다 — **시장 데이터
갱신**(주가·배당·환율), **웹폰트**(Pretendard·IBM Plex Mono), 그리고 키를 넣었을 때의
**Claude 설명**. 셋 다 실패해도 서비스는 그대로 동작합니다. 데이터는 마지막으로 받은
스냅샷을 쓰고, 폰트는 시스템 폰트로 떨어지고, 설명은 규칙 기반 생성기가 씁니다.

## 다른 머신에서 이어서 작업하기

저장소를 클론하면 **설치 단계 없이 바로 돕니다.** 파이썬 3.9 이상만 있으면 됩니다.

```
git clone <저장소 주소> && cd <디렉터리>
python3 tools/selfcheck.py --start     # 서버를 띄워 전체를 점검하고 끔
python3 server.py                      # http://127.0.0.1:8770
```

`make` 가 있으면 `make run` · `make test` · `make check` · `make refresh` 로도 됩니다.

세 가지가 다른 머신에서도 이어지도록 준비돼 있습니다.

| | 어떻게 |
| --- | --- |
| **코드·데이터** | 시장 데이터는 `data/market.seed.json` 로 저장소에 들어 있습니다. 갱신되는 캐시(`data/market.json`)는 git 에서 제외하고, 없으면 seed 를 복사해 시작합니다 — 클론 직후에도 인터넷 없이 첫 실행이 됩니다. 대신 갱신할 때마다 working tree 가 더러워지지 않습니다. |
| **의존성** | 없습니다. 표준 라이브러리만 씁니다. 설명을 Claude 가 쓰게 하려면 `pip install -r requirements-optional.txt` 와 `ANTHROPIC_API_KEY` 만 추가하면 됩니다. |
| **맥락** | `CLAUDE.md` 에 **코드를 읽어도 알 수 없는 것**을 적어 뒀습니다 — 이 프로젝트가 원본 서비스를 역산해서 만들어졌다는 사실, 건드리면 조용히 깨지는 여섯 가지, 이 환경에서만 겪는 문제(야후 429 차단 등), 다음에 할 만한 것. 새 머신에서 Claude Code 를 열면 이 파일이 먼저 읽힙니다. |

### 클론한 뒤 확인할 것

```
python3 -m unittest discover -s tests -t .   # 55개 통과해야 정상
python3 tools/selfcheck.py --start           # 12개 항목, 받은 값까지 같이 찍음
```

정합성 테스트는 `tests/golden/` 의 고정 스냅샷과 비교하므로 **네트워크 없이도 같은
결과**가 나옵니다. 통과하지 않으면 환경 문제가 아니라 코드 문제입니다.

### 데이터가 오래됐을 때

`data/market.seed.json` 의 기준월이 지나 있으면 서버가 뜰 때 백그라운드로 새로 받습니다
(`DIVIDEND_PLANNER_AUTO_REFRESH=0` 으로 끌 수 있음). 화면 오른쪽 위 ↻ 버튼이나
`python3 tools/refresh_market_data.py` 로 직접 받을 수도 있습니다.

seed 자체를 새 스냅샷으로 갱신하려면:

```
python3 tools/refresh_market_data.py
cp data/market.json data/market.seed.json     # 새 스냅샷을 저장소에 반영
```

### 2. 브라우저로 보기

서버는 기본으로 `127.0.0.1` 에만 붙습니다. 원격 장비에서 돌리고 있으면 세 가지 방법이
있습니다.

**(a) code-server 포트 프록시** — 브라우저 VS Code 로 작업 중이라면 이게 제일 쉽습니다.
code-server 를 열어 둔 주소 뒤에 `/proxy/8770/` 을 붙이면 됩니다.

```
https://<code-server 주소>/proxy/8770/
```

이 앱은 **경로 접두어가 붙어도 그대로 열립니다.** 자산을 상대 경로로 참조하고, 라우트를
한 칸 깊이(`/plan`, `/ticker`)로만 쓰고, 자기 `<script>` 태그의 URL에서 기준 경로를
계산합니다. `tests/test_api.py` 의 `BasePathIndependence` 가 이 규칙을 지킵니다 —
CSS 자리에 `index.html` 이 돌아오면 화면만 밋밋해지고 콘솔에는 아무것도 안 남아서,
사람이 눈치채기 전에 테스트가 잡아야 합니다.

**(b) SSH 포트 포워딩** — 내 컴퓨터의 `localhost:8770` 으로 끌어옵니다.

```
ssh -N -L 8770:127.0.0.1:8770 사용자@호스트
# SSM 만 열려 있으면
aws ssm start-session --target i-xxxxxxxx \
  --document-name AWS-StartPortForwardingSession \
  --parameters '{"portNumber":["8770"],"localPortNumber":["8770"]}'
```

**(c) 직접 노출** — `--host 0.0.0.0` 으로 열 수 있지만 **이 서비스에는 인증이 없습니다.**
방화벽·보안 그룹이 막아 주는 신뢰하는 망에서만 쓰세요.


## 무엇을 하는가

세 단계입니다.

1. **목표 역산** — 나이·은퇴 나이·가구 구성·주거 형태·소득·지출·연금을 받아 은퇴 시점에
   배당으로 채워야 할 월 금액을 계산합니다. 모르는 항목은 비워두면 연령대 중위소득과
   평균 소비성향 통계로 추정하고, **무엇을 추정했는지 화면에 남깁니다.**
   최소/적정/여유 세 시나리오를 함께 보여줍니다.
2. **포트폴리오 설계** — 배당 목적으로 선별한 36종목 유니버스를 다섯 개 팩터로 점수화해
   10종목을 고르고 비중을 정합니다. 남은 기간이 길수록 배당성장 쪽으로, 짧을수록
   현재 배당수익률 쪽으로 가중치가 옮겨갑니다. **기본 구성은 ETF 코어(60%)** 이고,
   개별주가 배당수익률과 성장률을 보완합니다 — 슬라이더로 0~100% 조정할 수 있습니다.
3. **검증** — 같은 비중으로 과거에 실제로 적립했다면 어떤 배당이 들어왔을지 실측
   주가·배당·환율로 백테스트하고, 앞으로의 전망은 과거 성장률에 보수적 할인을 씌워
   따로 계산합니다. **전망과 실측을 섞지 않습니다.**

각 종목 행을 클릭하면 그 종목이 왜 선택됐는지 팩터 점수 분해로 보여줍니다.

### 시그니처 화면 — 배당 입금 달력

계획 화면 가운데의 연 × 월 격자가 이 서비스의 중심입니다. 칸 하나가 백테스트에서 그 달
통장에 실제로 들어온 배당이고, 진할수록 많이 들어온 달입니다. 미국 종목의 3·6·9·12월
분기 배당과 국내 종목의 결산 배당이 어디에 몰리는지, 연금처럼 고르게 들어오는 현금흐름을
만들려면 무엇이 부족한지가 한눈에 보입니다. 배당 투자에서 실제로 중요한 건 연 수익률이
아니라 **매달 얼마가 들어오는가**라서, 그걸 화면의 주인공으로 뒀습니다.

`etf_ratio_effective`(미국 비중으로 깎인 값) · `etf_weight`(섹터 상한까지 적용한 실제
비중) · `etf_count` 가 함께 옵니다.

## 계산 방식

숨긴 것이 없습니다. 화면에 보이는 숫자가 계산에 쓰인 숫자입니다.

### 목표 역산 (`dividend_planner/goal.py`)

* 은퇴 후 필요 생활비 = 현재 지출 × 70% × 시나리오 배수(최소 0.78 / 적정 1.0 / 여유 1.3)
  \+ 주거 가산액(자가 0원, 전세 15만원, 월세 50만원)
* 계산값이 국민연금연구원 노후보장패널 기준 노후생활비보다 낮으면 **통계값을 하한**으로 씁니다
  (가구 구성별로 다름 — 부부 적정 324만원 등). 하한이 적용됐는지 화면에 표시합니다.
* 물가상승률 연 2.5%로 은퇴 시점 금액으로 환산한 뒤 예상 연금을 빼면 배당으로 채울 금액
* 필요 총자산 = 목표 월 배당 × 12 ÷ 세후 포트폴리오 배당수익률
* 비운 항목 추정: 세후 소득은 가장 가까운 연령대의 중위소득, 지출은 소득 × 소비성향 65%,
  월 투자 가능액은 소득 − 지출

### 팩터 점수와 비중 (`dividend_planner/portfolio.py`)

점수는 **유니버스 36종목 안에서의 백분위**입니다(동점은 평균 순위). 필터를 통과했는지와
무관하게 항상 36종목 기준이라, 조건을 바꿔도 종목의 점수 자체는 흔들리지 않습니다.

| 팩터 | 재료 |
| --- | --- |
| 현재 배당수익률 | 최근 12개월 주당 배당 ÷ 현재가 |
| 배당성장률 | 5년 연평균(없으면 10년) |
| 안정성 | 변동성 20% + 최대낙폭 15% + 연속증가 35% + 삭감 없음 30% |
| 총수익 | 최근 10년 배당 재투자 총수익 CAGR |
| 현금흐름 평탄화 | 연간 지급 횟수 |

프로파일 가중치는 남은 기간으로 정합니다 — 15년 이상 `growth`, 8~15년 `balanced`,
8년 미만 `income`. 위험 성향은 안정성 가중치를 0.35 / 0.25 / 0.15로 바꾸고 나머지 넷을
비례 조정합니다.

비중은 **종합 점수의 제곱에 비례**합니다. 제곱을 쓰면 점수 차이가 비중 차이로 또렷하게
드러나면서도 하위 종목이 0으로 사라지지 않습니다. 여기에 세 제약이 걸립니다.

* **ETF 비중** (`etf_ratio`, 기본 0.6) — ETF·미국 개별주·국내 개별주 세 바구니로 나눠
  각 바구니의 비중 합과 종목 수를 정합니다. 유니버스의 ETF는 모두 미국 상장이라
  **ETF 비중은 미국 비중을 넘을 수 없습니다** — 넘겨받으면 미국 비중까지 깎고,
  깎았다는 사실을 화면에 적습니다. `null`을 넘기면 제약 없이 점수만으로 고릅니다
  (참조 서비스와 같은 동작 — 정합성 테스트가 이 경로를 씁니다).
* **미국/국내 시장 비중** (`us_ratio`)
* **섹터 상한 30%** — 넘는 섹터를 눌러 담고 여유 있는 종목에 재배분합니다 (ETF는 자체
  분산되어 제외)

그래서 **점수 순서와 비중 순서가 어긋날 수 있습니다.** 표의 「역할」 칸이 그 이유를
구분해 보여 줍니다 — ETF는 점수가 높아서가 아니라 **코어**라서 담겼고, 개별주는
개별주끼리의 점수 순서(강력 추천 / 추천 / 분산 편입)로 담겼습니다.

### ETF 비중을 올리면 무엇이 바뀌는가

시드 5,000만원 · 월 200만원 · 25년 · 중립형 · 미국 75% 기준으로 재 본 값입니다.

| ETF 비중 | 실제 ETF% | 시작 배당수익률 | 배당성장률 | 전망 월배당 | 백테스트 MDD | 가중 변동성 |
| --- | --- | --- | --- | --- | --- | --- |
| 0% | 0.0% | 3.41% | 7.81% | 9,912,312원 | −20.79% | 22.6% |
| 20% | 20.0% | 3.13% | 7.94% | 9,022,150원 | −20.42% | 20.9% |
| **60% (기본)** | **61.8%** | **2.94%** | **7.02%** | **6,216,326원** | **−22.67%** | **18.1%** |
| 100% | 75.0% | 2.34% | 6.30% | 3,681,860원 | −18.34% | 16.8% |

트레이드오프가 뚜렷합니다. ETF를 늘리면 **변동성은 내려가고**(22.6% → 16.8%) 종목 하나에
대한 의존도 사라지지만, **배당수익률과 전망 배당은 줄어듭니다.** 같은 목표를 채우려면
적립액을 더 넣거나 기간을 늘려야 합니다.

주의할 점 하나 — 기본값 60%에서 백테스트 MDD가 −22.67%로 0%보다 오히려 깊습니다.
ETF가 미국 쪽을 채우면서 남은 국내 자리가 금융 섹터에 몰리고(섹터 상한 30%에 걸림)
그쪽 낙폭이 커진 결과입니다. **ETF 코어가 곧 낮은 낙폭을 보장하지는 않습니다.**
100%(실제 75%)까지 올리면 −18.34%로 내려갑니다.

ETF 비중을 100%로 올려도 실제 ETF 비중은 미국 비중(기본 75%)에서 멈춥니다. 유니버스에
국내 상장 ETF가 없기 때문입니다 — 배당 이력을 주는 공급자(야후·알파밴티지)에 닿는
환경이면 국내 ETF를 유니버스에 추가할 수 있습니다.

유니버스에서 빠지는 종목은 두 종류입니다. 데이터 이력이 백테스트 기간보다 짧은 종목,
배당수익률이 1% 미만인 종목. 왜 빠졌는지 화면에 이유를 적습니다.

### 백테스트 (`dividend_planner/engine.py`)

전망이 아니라 실측입니다. 매달 월말 종가로 목표 비중대로 매수하고(수수료 0.1%),
배당은 원천징수(미국 15% / 국내 15.4%) 후 같은 달에 재투자하며, 1월에 목표 비중으로
리밸런싱합니다. 미국 종목은 월말 원달러 환율로 환산합니다.

* 총수익 CAGR = (기말 평가액 ÷ 총 투입 원금)^(12/개월수) − 1
* 최대낙폭 = 평가액 시계열의 최대 낙폭 (적립이 계속되므로 종목 단위 MDD보다 얕습니다)
* 투입 원금 대비 배당(YoC) = 최근 12개월 배당 ÷ 총 투입 원금
* 배당 재투자를 끄면 배당은 통장으로 나간 돈이라 평가액에 더하지 않고, 받은 현금은
  `cash_dividends`로 따로 보고합니다

### 전망 (`dividend_planner/engine.py`)

결정론적 모형입니다. 매월 이렇게 굴립니다.

```
평가액 = 평가액 × (1 + 주가상승률/12) + 월 적립액
월 배당 = 평가액 × (시작 배당수익률/12) × (1 − 세율) × ((1+배당성장률)/(1+주가상승률))^(t/12)
재투자 시 평가액 += 월 배당
```

가정은 포트폴리오 비중으로 가중해 만듭니다. 시작 배당수익률은 가중 평균 배당수익률,
배당성장률은 가중 평균 과거 성장률에 **0.7배 할인**, 주가상승률은 (가중 총수익 CAGR −
가중 배당수익률)에 0.7배 할인하고 **연 7% 상한**을 씌웁니다. 필요 월 적립액은 목표를
정확히 채우는 값을 이분 탐색으로 찾습니다. 목표 도달 시점은 투자 기간을 넘겨서도
(최대 50년) 찾아 알려줍니다.

## 데이터

`data/market.json` 한 파일에 다 들어 있습니다 — 36종목의 월말 종가와 월별 주당 배당금,
그리고 원달러 환율 월별 시계열. 종목 지표는 서버가 뜨면서 이 원시 시계열로 다시 계산하므로,
저장된 지표와 화면의 지표가 어긋날 일이 없습니다. 이 파일은 **캐시**입니다 — 기준월이
지나 있으면 서버가 뜰 때 백그라운드로 새로 받고, 받은 팩으로 스냅샷을 통째로 교체합니다
(교체 중에 들어온 요청도 일관된 스냅샷을 봅니다).

화면 오른쪽 위의 ↻ 버튼을 누르면 지금 바로 받습니다. 진행 상황이 종목별로 흐르고,
어느 공급자에서 받았는지 그 자리에서 보입니다. 명령줄로도 됩니다.

```
python3 tools/refresh_market_data.py                 # 받아서 저장
python3 tools/refresh_market_data.py --dry-run       # 받아만 보고 저장 안 함
python3 tools/refresh_market_data.py --only SCHD,KO  # 일부 종목만 (나머지는 캐시 유지)
```

### 공급자

한 곳이 막히면 다음으로 넘어갑니다. 공급자마다 주는 것이 다릅니다.

| 공급자 | 주는 것 | 범위 | 비고 |
| --- | --- | --- | --- |
| 야후 파이낸스 | 월말 종가 + **월별 배당** + 상장일 | 미국·국내 | 1순위. 한 번 호출로 다 온다 |
| 알파밴티지 | 월말 종가 + **월별 배당** | 미국 | `ALPHAVANTAGE_API_KEY` 필요 |

**배당 이력을 주는 공급자에 닿지 못하면 캐시의 배당을 그대로 쓰고 그 사실을 밝힙니다.**
가격은 최신, 배당은 스냅샷 기준 — 이 상태가 종목 화면과 상단 신선도 배지에 그대로
표시됩니다(`price_source`, `dividend_source`). 조용히 옛 숫자를 새 숫자처럼 보여주지
않는 것이 이 설계의 요점입니다.

한 공급자가 연달아 실패하면 그 갱신에서는 더 두드리지 않습니다. IP가 막힌 경우
36종목마다 재시도하면 몇 분을 그냥 버립니다.

### 이력 이어 붙이기

공급자가 10년치만 주면 15년 백테스트를 못 하게 됩니다. 그래서 새 시계열 앞쪽에 캐시의
오래된 달을 이어 붙입니다 — 단, **겹치는 구간의 중위 오차가 2% 이내일 때만**. 서로 다른
기준(액면분할·배당 조정)의 가격을 한 줄로 이으면 그 이음매가 가짜 급등락으로 남기
때문입니다. 이어 붙인 종목은 출처가 `나스닥+캐시`처럼 표시됩니다.

백테스트 기간 슬라이더의 상한도 데이터가 정합니다. 포트폴리오 한 벌(10종목)을 채울 만큼
종목이 남는 최장 기간까지만 허용합니다 — 공급자가 10년치만 줬으면 15년 옵션은 애초에
나오지 않습니다.

### 환율

미국 종목을 원화로 굴릴 때 매수 단가, 평가액, 배당이 **모두 환율에 선형**이라 환율에
상수를 곱하면 그대로 상쇄됩니다. 그래서 백테스트 결과는 환율의 절대 수준에 불변이고,
상대 변화만 남습니다. 다만 절대 환율을 알면 종목 화면에 원화 환산가를 보여줄 수 있어서,
받을 수 있으면 실제 환율(ECB 기준)을 그대로 저장합니다. 예전 팩처럼 지수만 있으면
원화 환산은 표시하지 않습니다 — 모르는 값을 그럴싸하게 지어내지 않습니다.

## 설명 엔진

`이 전략을 왜 이렇게 짰는가` 패널은 두 경로 중 하나로 채워집니다.

* `ANTHROPIC_API_KEY`가 있고 `anthropic` SDK가 설치돼 있으면 **Claude**가 서술합니다
  (`pip install anthropic`, 모델은 `DIVIDEND_PLANNER_MODEL`로 바꿀 수 있고 기본은
  `claude-opus-5`)
* 없으면 **규칙 기반 생성기**(`dividend_planner/narrative.py`)가 같은 구조로 서술합니다

어느 쪽이든 계약은 같습니다 — **표에 없는 숫자를 새로 만들지 않습니다.** 두 경로 모두
SSE(`phase`/`delta`/`final`/`error`)로 스트리밍하고, 같은 조건이면 캐시에서 즉시 돌려줍니다.
Claude 호출이 실패하면 조용히 규칙 기반으로 갈아탑니다. 기본 상태(키 없음)에서도
설명 패널은 정상 동작합니다.

### 참조 서비스와 다른 점

원본은 일별 시세를 쓰고 이 서비스는 월말 종가만 씁니다. 그래서 두 가지가 구조적으로 조금
다릅니다. 공식 차이가 아니라 데이터 해상도 차이입니다.

* **최대낙폭(MDD)** — 월말 값만 보면 장중·월중 저점을 놓칩니다. 종목 단위로 최대 10%p
  차이가 납니다(대부분은 1%p 미만).
* **상장 10년 미만 종목의 총수익 CAGR** — VICI 한 종목이 해당하며 0.4%p 차이.

이 차이가 안정성 팩터 점수를 미세하게 흔들어, 17개 참조 시나리오 중 **하나**(미국 100%)에서
10번째 종목이 CVX 대신 PEP로 바뀝니다. 나머지 16개는 종목 구성이 같고 비중 오차도
합계 6% 미만입니다.

의도적으로 다르게 만든 것도 하나 있습니다. 원본은 목표 화면의 `필요 총자산`을 계획 화면과
다른 배당수익률로 계산해서 두 화면의 숫자가 서로 어긋납니다. 이 서비스는 목표 화면도 계획
화면과 **같은 포트폴리오**로 계산해 두 숫자를 맞췄습니다.

국내 100%(`us_ratio=0`)는 6종목·3섹터가 모두 30% 상한에 걸리는 퇴화 케이스입니다. 원본은
여기서 상한을 넘긴 결과를 내놓는데, 이 서비스는 상한을 지키는 쪽을 택했습니다.

## 면책

공개 시장 데이터를 이용한 **시뮬레이션 도구**이며 투자 권유나 자문이 아닙니다. 과거 성과는
